# SEARCHING pass 2 — silicon diagnosis, test, DFT, and ECO

Private research notes. Research cutoff: September 2026. No implementation or experiments performed. No survivor in this cluster.

Four mechanisms were serious enough to examine; each reduces to existing machinery or lacks a new operation. The strongest shared wall is **insufficient distinguishability under constrained observation and intervention**, which is more fundamental than missing debug automation.

“Strongest” below means the strongest directly relevant baseline found for the specified subproblem, not a field-wide ranking across incomparable tools.

## 1. Intervention-based diagnosis that distinguishes observationally identical causes — KILL

- **Recent limitation:** Wit-HW, August 20, 2025, §VI, cannot separate buggy and innocent statements that always execute or whose execution conditions coincide. Additional passing witnesses cannot distinguish identical coverage spectra. AutoFlows++, April 2026, §VIII, still proposes richer message semantics, partial supervision, and joint control/data dependence inference. These are different manifestations of lost causal distinctions. [Wit-HW](https://arxiv.org/html/2508.14414v1), [AutoFlows++](https://arxiv.org/html/2604.15359v1)
- **Baseline:** Wit-HW generates similar but diverse passing executions and applies spectrum-based localization. AutoFlows++ slices communication interfaces, ranks candidate paths, and uses positional information to constrain interleaved message assignment.
- **Exact wall:** Several distinct faults or histories induce the same allowed observations. This is **fundamental relative to that observation interface**; ranking or more samples of the same kind cannot recover erased information.
- **Proposed primitive examined:** Construct equivalence classes of fault hypotheses under all currently allowed observations; synthesize a bounded intervention policy that splits every distinguishable class while preserving permitted system behavior.
- **Adjacent reduction:** This is active diagnosis of partially observed discrete-event systems. Haar et al. already synthesize controllers with optimal computational complexity and memory requirements, including detection-delay/permissiveness tradeoffs. Causality-guided adaptive interventional debugging already selects fault-injection interventions to expose causal relationships. These are much stronger novelty threats than generic “causal inference exists.” [Haar et al., JCSS 2017](https://www.sciencedirect.com/science/article/pii/S0022000016300198), [Causality-Guided Adaptive Interventional Debugging, 2020](https://arxiv.org/abs/2003.09539)
- **Cheapest kill:** Translate the proposed hardware intervention model into Haar’s controlled plant. If the policy objective and admissible interventions translate without a new theorem or representation, novelty is gone. This reduction already appears straightforward.
- **Would-be reusable object:** A diagnosability-preserving quotient and separating controller. Valuable objects, but already established objects in adjacent theory.

**Post-silicon corroboration:** Fuzzilicon, NDSS 2026, pp. 7–8 and §VII, supplies microcode-level instrumentation, but has only 16 hooks, requires reruns, restricts self-modifying inputs for its serialization oracle, and needs microcode patch access. It also reports that instrumentation can induce speculative behavior that would not arise naturally. These limitations do not imply an algorithm can recover unavailable internal state without assumptions. [Fuzzilicon](https://www.ndss-symposium.org/wp-content/uploads/2026-s1486-paper.pdf)

## 2. Fault-separating test cubes instead of fully assigned SAT witnesses — KILL

- **Recent limitation/baseline:** PastATPG, DAC June 22–25, 2025, directly attacks SAT-based ATPG’s overassignment problem: complete primary-input assignments restrict compaction and inflate pattern counts. Its PA-MiniSat solver returns partial assignments using full-literal watching; the flow combines this with structural ATPG. [Primary IEEE abstract](https://ieeexplore.ieee.org/document/11132425/)
- **Exact wall:** A satisfying assignment contains commitments irrelevant to detecting its target fault, consuming freedom that could detect other faults simultaneously. This is primarily **a solver-output/optimization mismatch**, not an information-theoretic impossibility.
- **Proposed primitive examined:** Return a residual input cube plus the set of faults guaranteed detectable under every completion; support cube composition without losing those guarantees.
- **Adjacent reduction:** Partial-assignment SAT already removes unnecessary commitments; guaranteed completion sets are implicants, and selecting compatible cubes becomes covering/packing or multi-target ATPG. “Make the solver return a fault-aware residual instead of one model” is not sufficiently distinct without an additional algebraic closure result.
- **Cheapest kill:** Express the proposed residual and composition rule as ordinary implicant extraction plus fault simulation/ATPG. Compare the operation against PA-MiniSat’s actual output before claiming a new primitive.
- **Would-be reusable object:** Compact detection cubes and composition rules. No new rule emerged beyond existing implicant and test-compaction machinery.

**Related chiplet warning:** Extendable E2I-TEST, ETS May 26, 2025, already extends a 16-pattern, size-independent construction beyond matching stacked-die neighborhoods by incorporating interposer wires, TSVs, and micro-bump adjacency. Its original 16-pattern guarantee must not be generalized to arbitrary neighborhood graphs. [imec primary record](https://imec-publications.be/entities/publication/31c93b2d-6acd-4b4b-855a-b1f2b7113351/full)

Pomeranz’s April 13, 2026 TODAES paper also already identifies functionally undetectable interconnect faults and changes the interconnect configuration to remove them. Thus “co-design the physical mapping and the tests to make previously hidden faults visible” is an existing mechanism. [Functionally Undetectable Interconnect Faults](https://doi.org/10.1145/3798108)

## 3. A synthesis calculus that retains polynomial test generation after optimization — KILL in its present form

- **Recent limitation/baseline:** Schnieber and Drechsler, ETS 2026, *Path Delay Fault Testable KFDD Circuits with Polynomial Test Pattern Generation*, §V, explicitly ends with hardware-overhead reduction and larger-design applicability as future work. They already transform KFDD-derived circuits to obtain strong robust path-delay tests and polynomial pattern-generation operations. [Author-hosted paper](https://www.ag-rn.tzi.de/doc/konf/ETS2026_MS.pdf)
- **Exact wall:** The tractable representation and inserted test controls constrain implementation structure and increase area. This is **a representation/implementation tradeoff**. Some overhead may be removable engineering; there is no evidence all overhead can be removed while retaining the guarantees.
- **Proposed primitive examined:** Attach to each local circuit rewrite a transformer for fault-sensitization witnesses, so synthesis can optimize while preserving efficient derivation of robust tests.
- **Adjacent/older threat:** Local circuit transformations that preserve or improve robust path-delay testability were already studied in 1994–95. Testability-oriented synthesis from decision diagrams dates to 1992; the 2004 BDD construction uses an added input and inverter. A “testability-preserving rewrite calculus” needs a genuinely different preserved property or composition theorem. [University publication catalogue with original abstracts](https://ira.informatik.uni-freiburg.de/en/src/publications_short_tfi.php.html)
- **Cheapest kill:** Take the proposed local witness transformer and compare it to the existing local-transformation testability conditions. If it is those conditions with new annotations, kill. If global composition is essential, first exhibit a small case where locally valid transformations fail and state the new composition rule.
- **Would-be reusable object:** A transformation algebra preserving test-generation tractability. This would be structurally useful, but the current proposal duplicates an established research line.

**Important scope corrections for the 2026 paper:** Polynomial bounds are relative to the relevant representation, not a polynomial-size representation guarantee for arbitrary functions. Table IV’s M1/M3 “100%” qualification excludes paths originating at test signals; M2 reaches 100% including those paths. Table II shows substantial overhead: b11 uses 646 gates in the optimized STD-library circuit versus 4,714 for M2. This is a real open tradeoff, not an unclaimed universal testing breakthrough.

## 4. Support-complete ECO synthesis and schedule-preserving change transport — KILL / exclusion overlap

- **Recent limitations/baselines:** Tung et al., DAC 2025, systematically collect and validate feasible sets of rectification signals from a supplied candidate set, then group/rank signals for small patches. The baseline is not merely trial-and-error single-point repair. [Official DAC presentation abstract](https://62dac.conference-program.com/presentation/?id=RESEARCH1943&sess=sess129)
- Azadi et al., April 15, 2026, §§V-E/VI, expose HLS ECO limitations: graph-edit computation approaches scalability limits, the XLS equivalence checker cannot handle their stateful `proc` cases, and state/schedule mismatches obstruct downstream checking. Their Histogram RTL check did not complete; FIR and Vector Core show state mismatch in Table VIII. [Graph-Based ECO and Patch Generation for HLS](https://arxiv.org/html/2604.14248v1)
- **Exact wall:** Small source edits can cause nonlocal structural/scheduling changes. Candidate-support search, graph matching, and sequential correspondence are separate computational problems. Some pipeline glue is engineering debt; unrestricted compact change transport is not established.
- **Proposed primitives examined:** An oracle returning all minimal feasible patch supports; a change operator that transports edits through scheduling while retaining reusable state correspondence.
- **Prior-art/exclusion result:** The first substantially overlaps Tung’s existing support-validation direction. The second immediately returns to previously excluded DeltaRTL/conditional equivalence/proof-reuse territory unless a new algebraic operation is specified. Faster graph-edit search, incremental scheduling, or added verification would fail the centerpiece test.
- **Cheapest kill:** For support enumeration, compare exact feasible-set semantics and quantifiers against Tung’s algorithm. For transport, construct two optimizations producing equivalent but differently scheduled pipelines and identify what the alleged operator computes beyond correspondence plus patch synthesis.
- **Would-be reusable object:** A support relation or compositional edit derivative. Neither currently contains a distinct surviving principle.

**Commercial pressure:** Cadence’s current Conformal products already advertise pre-/post-mask functional ECO, physical implementation constraints, and sequential changes. Easy-Logic’s 2025 flow includes hierarchy/replication and floorplan guidance. These are capability disclosures, not evidence of their internal algorithm or universal success. [Cadence](https://www.cadence.com/en_US/home/tools/digital-design-and-signoff/conformal-technologies.html), [Easy-Logic, July 2025](https://www.easylogiceda.com/en/col77/79)

## Newly excluded mechanism families

The newly excluded families are **generic active diagnosis for hardware; partial-assignment/multi-fault test compaction presented as a new primitive; generic testability-preserving local synthesis; and support enumeration or schedule-preserving ECO without a new composition principle**. The fields remain open; these particular mechanisms do not justify advancing.
